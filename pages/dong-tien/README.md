# Dòng tiền

Registration and email-only login use the existing admin service. Registration creates a CRM lead with `page_id=dong-tien` and returns a signed learning session. Login checks the registered email on this page only. Both flows open `/dong-tien/learn`, which selects the first unfinished lesson. Learner IDs are CRM registration IDs.

Copy `.env.example` to `.env.local`, configure `ADMIN_API_URL` and the admin's `LEAD_API_KEY`, then run `npm install` and `npm run dev`. Start the admin service separately on port 3001. Set `DONG_TIEN_SESSION_SECRET` or the existing `JWT_SECRET` on the admin service. Learning sessions expire in 24 hours and have their own token audience/issuer. The API key stays on the server.

Run `npm run db:migrate` from the repository root with PostgreSQL available. Migration `006_dong_tien_learning.sql` adds the course catalog, learner metadata and progress tables. Import actual Vimeo lessons with `node scripts/import-dong-tien-lessons.js <catalog.json>`. The input is a JSON array of `{ id, title, vimeo_video_id, duration, position, is_visible }`; duration is in seconds, and unlisted IDs can include their privacy hash (`VIDEO_ID/HASH`). No placeholder videos are seeded. Private folder links require access and are not video IDs.

`course-catalog.json` contains the seven dòng tiền lessons, ordered from Bài 1 to Bài 7, with real Vimeo IDs, privacy hashes and durations. Import it from the repository root with `node scripts/import-dong-tien-lessons.js pages/dong-tien/course-catalog.json`. `vimeo-catalog.json` preserves metadata for all 23 videos in the supplied review folder; it is not automatically imported. Both files use stable Vimeo video IDs as lesson IDs. The review extraction helper in `scripts/vimeo-review-catalog.browser.js` reads an accessible folder through `agent-browser eval --stdin` and omits temporary player signatures.

Progress stores resume position, furthest position, watched ranges, playback speed, watched percentage and completion time in `dong_tien_progress`. Completion requires 95% unique watched coverage. Seeking, switching lessons and submitting surveys do not mark the video watched. Periodic saves, pause and page-hide saves use the new API; offline queues are scoped by email and brand. Surveys link to the lead and page in the existing `surveys` table, with per-lesson answers and onboarding status in `dong_tien_learners`.

All Dòng Tiền routes share public/js/funnel-tracker.js and public/js/meta-pixel.js from the parent project through same-origin server proxies. ProjectTracking in _app tracks route changes once; modal query changes do not create page views. Attribution/session state uses the same shared runtime as static funnels. Pixel and Google Tag settings are read from src/trackingConfig.js on the root server, not child environment variables. Events and users remain in the root CRM database. Registration creates one browser conversion with the CRM registration ID; Dong Tien APIs do not dispatch CAPI or webhooks; repeat registrations and email login do not convert again. Old CRM/backend webhooks remain disconnected. See AUDIT.md for the cleanup inventory and shared configuration.

Vimeo remains for video playback with `dnt=1` and no referrer. The application creates its iframe directly without an oEmbed request from the application document. Vimeo still receives the connection needed to serve video. Fonts, photos, QR images and the former TradingView chart are served locally; the chart is a static capture dated 06/10/2026. Zalo links open only on user action and use `noreferrer`. The Content Security Policy permits same-origin APIs, Vimeo frames and the configured Meta/Google tags; remote image optimization and DNS prefetch are disabled. The server proxy accepts only loopback/private IPv4 admin addresses and refuses redirects. Set `NEXT_TELEMETRY_DISABLED=1` for development/builds, as in `.env.example`. Browser events now use `/dong-tien/api/track`.

The learning repository supports JSON fallback only for an unreachable database during development. Production requires PostgreSQL. Missing migrations and SQL errors fail explicitly. Development fallback data must be imported before switching stores if it contains real learner records.

Validation: `node scripts/test-dong-tien-learning.cjs` and `npm run check:types --prefix pages/dong-tien`.

Admin > Funnels > dong-tien opens the learning manager at `/admin/view/funnels?funnel=dong-tien`. It has overview, learner/history and lesson tabs; there is no email statistics tab. Reports read internal registrations, events, progress and survey answers. A session count means a recorded lesson opening; lesson viewer counts are unique learners. Date filters select registration cohorts and constrain opening history, while displayed progress is current cumulative progress. Completion totals use visible lessons in visible chapters.

Migration `007_dong_tien_stages.sql` adds chapter settings (existing `stage_*` database/API fields remain compatible). Administrators can create/edit/hide/delete/reorder chapters and lessons, assign chapters individually or in bulk, filter by chapter, and drag/drop or move lessons up/down within a chapter. Chapter order and lesson order within each chapter also control the learning playlist and navigation. Deletion hides content while preserving progress. Chapter deletion moves lessons to the unclassified group. Surveys appear at the configured video time and save to the internal learner/survey tables without marking a video complete. The learner export is a UTF-8 CSV compatible with Excel.

The Vimeo import dialog fetches all video pages from the shared review folder directly. It can select all videos, assign an optional chapter and publish new imports or leave them hidden for organization. New lessons are visible by default; uncheck the visibility option to import drafts. Existing lesson visibility, titles, chapter assignment, survey settings and progress are preserved unless an import chapter is explicitly selected. Video IDs are matched before creating new records, so custom lesson IDs do not cause duplicates. Optional server-only `VIMEO_ACCESS_TOKEN` and `DONG_TIEN_VIMEO_FOLDER_ID=29758694` use the authenticated folder API instead. `DONG_TIEN_VIMEO_REVIEW_URL` overrides the shared review folder. Short-lived review credentials remain in memory and are never returned to the browser or stored. If access fails, the admin displays an error instead of presenting stale metadata as a successful sync.

Learning URLs for deleted/hidden lessons automatically replace the old route with the first unfinished visible lesson (or the first visible lesson when all are complete). An empty catalog displays a recoverable message. The catalog refreshes when the learning tab regains focus, becomes visible, and every 30 seconds while visible; background refresh preserves current playback position. Landing chapter CTAs resolve actual chapter IDs and order from the API instead of fixed lesson offsets. `--catalog-changes` in the browser test verifies stale routes, changing catalogs, empty-state handling and newly published lesson recovery.

Thumbnails are automatically fetched when adding/changing a Vimeo video and when importing it. The server downloads Vimeo image bytes into `STORAGE_ROOT/dong-tien-thumbnails` and stores a content-hashed local URL in the lesson record. Admin and learning pages load these through same-origin endpoints. Copy that storage folder when moving an existing deployment, or reimport its videos to regenerate the thumbnails. Vimeo requests carry only video/folder metadata, never learner records or learning events. Detailed learning progress and surveys remain internal; marketing events use the root browser Pixel and Google Tag configuration. Vimeo keeps DNT playback.

`node scripts/test-dong-tien-admin.cjs --browser` validates admin API permissions, statistics, configuration persistence and browser edits with isolated storage. Add `--survey` to the real-video browser command below to verify timed survey display and submission as well.

`node scripts/test-dong-tien-vimeo.cjs` verifies pagination, unlisted video hashes, thumbnail caching and restricted request destinations with mocked Vimeo responses.

With the local page running, `node scripts/test-dong-tien-browser.cjs pages/dong-tien/course-catalog.json --play-video` checks registration, login, the real first Vimeo video and watched coverage using isolated test storage. It creates no CRM test leads in the running admin database.
