# App học tập (Dòng Tiền, Trading)

Một app Next.js phục vụ mọi khóa học trong `src/lib/courses.ts` dưới `/<course>`: `/dong-tien` và `/trading`. Khóa học mới cần một mục trong file này, trong `src/learningCourses.js` của root, `next.config.ts`, trang `src/pages/<course>/` và location Nginx. Dữ liệu nằm trong các bảng `learning_*` theo cột `course`, không cần migration mới. Mọi khóa dùng chung tính năng học, khảo sát, tour, Zalo và đo lường; nội dung landing truyền vào `features/optin/OptinLanding.tsx`.

Link email/CRM có `?email=` tự đăng nhập học viên đã đăng ký (email chưa đăng ký mở form đăng ký điền sẵn). Script trong `<head>` xóa email khỏi URL trước khi Pixel, GTM và tracker đọc địa chỉ. UTM, click ID và referrer giữ theo phiên tab như các phễu khác; cookie email học viên lưu 14 ngày: khách quay lại landing được chuyển thẳng vào học (phiên còn hạn) hoặc tự đăng nhập lại bằng cookie (phiên 24 giờ đã hết). Đăng xuất xóa cookie; lỗi 401 giữ cookie nhưng trong tab đó chỉ điền sẵn email để tránh vòng lặp; `?action=register` hoặc `?dang-ky` luôn hiện form đăng ký; `?dang-nhap` mở form đăng nhập điền sẵn email từ cookie, không tự chuyển vào học.

Registration and email-only login use the existing admin service. Registration creates a CRM lead with `page_id=<course>` and returns a signed learning session. Login checks the registered email on this page only. Both flows open `/<course>/learn`, which selects the first unfinished lesson. Learner IDs are CRM registration IDs.

Copy `.env.example` to `.env.local`, configure `ADMIN_API_URL` and the admin's `LEAD_API_KEY`, then run `npm install` and `npm run dev`. Start the admin service separately on port 3001. Set `DONG_TIEN_SESSION_SECRET` or the existing `JWT_SECRET` on the admin service. Learning sessions expire in 24 hours and have their own token audience/issuer. The API key stays on the server.

Run `npm run db:migrate` from the repository root with PostgreSQL available. Migrations `006`/`007` created the original Dòng Tiền tables; `008_learning_courses.sql` moves every course to the shared `learning_*` tables. Import actual Vimeo lessons with `node scripts/import-learning-lessons.js <course> <catalog.json>`. The input is a JSON array of `{ id, title, vimeo_video_id, duration, position, is_visible }`; duration is in seconds, and unlisted IDs can include their privacy hash (`VIDEO_ID/HASH`). No placeholder videos are seeded. Private folder links require access and are not video IDs.

`course-catalog.json` contains the seven dòng tiền lessons, ordered from Bài 1 to Bài 7, with real Vimeo IDs, privacy hashes and durations. Import it from the repository root with `node scripts/import-learning-lessons.js dong-tien pages/dong-tien/course-catalog.json`. `vimeo-catalog.json` preserves metadata for all 23 videos in the supplied review folder; it is not automatically imported. Both files use stable Vimeo video IDs as lesson IDs. The review extraction helper in `scripts/vimeo-review-catalog.browser.js` reads an accessible folder through `agent-browser eval --stdin` and omits temporary player signatures.

Progress stores resume position, furthest position, watched ranges, playback speed, watched percentage and completion time in `learning_progress`. Completion requires 95% unique watched coverage. Seeking, switching lessons and CTA clicks do not mark the video watched. Periodic saves, pause and page-hide saves use the new API; offline queues are scoped by email and brand. Onboarding status is in `learning_learners`, which also keeps the answers of the former lesson survey (read-only in the learner detail).

All Dòng Tiền routes share public/js/funnel-tracker.js and public/js/meta-pixel.js from the parent project through same-origin server proxies. ProjectTracking in _app tracks route changes once; modal query changes do not create page views. Attribution/session state uses the same shared runtime as static funnels. Pixel and Google Tag settings are read from src/trackingConfig.js on the root server, not child environment variables. Events and users remain in the root CRM database. Registration creates one browser conversion with the CRM registration ID; Meta CAPI follows `capi` in `src/learningCourses.js`: registration once per new lead, landing views of new visitors (PageView/ViewContent/SubmitApplication with the Pixel's event ID) and the learning milestones StartLearning, CourseProgress50 and CompleteCourse once per learner; only Trading sends the n8n webhook; repeat registrations and email login do not convert again. Old CRM/backend webhooks remain disconnected. See AUDIT.md for the cleanup inventory and shared configuration.

Vimeo remains for video playback with `dnt=1` and no referrer. The application creates its iframe directly without an oEmbed request from the application document. Vimeo still receives the connection needed to serve video. Fonts, photos, QR images and the former TradingView chart are served locally; the chart is a static capture dated 06/10/2026. Zalo links open only on user action and use `noreferrer`. The Content Security Policy permits same-origin APIs, Vimeo frames and the configured Meta/Google tags; remote image optimization and DNS prefetch are disabled. The server proxy accepts only loopback/private IPv4 admin addresses and refuses redirects. Set `NEXT_TELEMETRY_DISABLED=1` for development/builds, as in `.env.example`. Browser events use `/<course>/api/track`.

The learning repository supports JSON fallback only for an unreachable database during development. Production requires PostgreSQL. Missing migrations and SQL errors fail explicitly. Development fallback data must be imported before switching stores if it contains real learner records.

Validation: `node scripts/test-dong-tien-learning.cjs`, `node scripts/test-learning-courses.cjs` and `npm run check:types --prefix pages/dong-tien`.

Admin > Funnels > <course> opens the learning manager at `/admin/view/funnels?funnel=<course>`. It has overview, learner/history, lesson and CTA tabs; there is no email statistics tab. Reports read internal registrations, events and progress. A session count means a recorded lesson opening; lesson viewer counts are unique learners. Date filters select registration cohorts and constrain opening history, while displayed progress is current cumulative progress. Completion totals use visible lessons in visible chapters.

Migration `007_dong_tien_stages.sql` adds chapter settings (existing `stage_*` database/API fields remain compatible). Administrators can create/edit/hide/delete/reorder chapters and lessons, assign chapters individually or in bulk, filter by chapter, and drag/drop or move lessons up/down within a chapter. Chapter order and lesson order within each chapter also control the learning playlist and navigation. Deletion hides content while preserving progress. Chapter deletion moves lessons to the unclassified group. The learner export is a UTF-8 CSV compatible with Excel.

**CTA.** The CTA tab manages one library shared by every course (`crm_settings` key `learning_ctas`, `src/learningCta.js`). A CTA is a Zalo invite, a link to another funnel or page, a Zoom sign-up (`/zoom`) or a plain message, with an optional Media Library image. It appears after a time, at a watched percentage or when the video ends, as a popup in the middle of the screen, a corner card (video keeps playing; below the video on phones) or an overlay inside the video frame (title and button only on phones); popup and overlay pause the video. Each CTA picks one of 13 daisyUI card templates (basic, badges, bottom image, centered, no image, bordered, dash, colour, neutral, close on top, side image, image overlay, pricing list), a daisyUI size (sm/md/lg) and a primary colour; the cards use daisyUI 5 card/button/badge CSS (MIT), renamed dz-* in src/styles/daisy-cta.css and src/admin/daisy-cta.css by scripts/build-daisy-cta-css.cjs, so the admin preview renders the same cards. CTA text uses Be Vietnam Pro, self-hosted by next/font. Images must come from the Media Library, because lesson pages only load same-site images (CSP). "How often" is every visit, once per lesson or once per course, optionally never again after a click; this history lives in the learner's browser. Each CTA chooses per course: no lessons, all lessons, chapters or selected lessons. An end-of-video CTA replaces the automatic move to the next lesson and offers "Bài tiếp theo" itself. Links open in a new tab; only `https://` and site paths are accepted. Views and clicks are `learning_cta_view` / `learning_cta_click` events, shown in the tab as unique learners per course and date range.

**Adding lessons from Vimeo links.** "+ Thêm bài từ link Vimeo" takes one link per line (share link `vimeo.com/ID/hash`, player link, `vimeo.com/manage/videos/…` or the embed code). The server reads title, duration and the privacy hash from Vimeo oEmbed (sending `PUBLIC_BASE_URL` as Referer, so domain-restricted videos answer); with an optional server-only `VIMEO_ACCESS_TOKEN` it falls back to the Vimeo API for private videos. Titles can be edited before adding; links whose video is already a lesson are skipped. The lesson form accepts a link too ("Lấy từ Vimeo" fills ID and duration, and offers the Vimeo title when editing). One video can be in only one lesson. A new lesson takes the Vimeo ID as its ID when that is free; lesson IDs never change when a lesson's video is replaced, so otherwise it gets the next free ID. A deleted lesson's ID (with its saved progress) is reused only when the same video is added again. The former folder sync was removed (it only read one fixed Dòng Tiền review folder).

Learning URLs for deleted/hidden lessons automatically replace the old route with the first unfinished visible lesson (or the first visible lesson when all are complete). An empty catalog displays a recoverable message. The catalog refreshes when the learning tab regains focus, becomes visible, and every 30 seconds while visible; background refresh preserves current playback position. Landing chapter CTAs resolve actual chapter IDs and order from the API instead of fixed lesson offsets. `--catalog-changes` in the browser test verifies stale routes, changing catalogs, empty-state handling and newly published lesson recovery.

Thumbnails are automatically fetched when adding or changing a Vimeo video. The server downloads Vimeo image bytes into `STORAGE_ROOT/dong-tien-thumbnails` and stores a content-hashed local URL in the lesson record. Admin and learning pages load these through same-origin endpoints. Copy that storage folder when moving an existing deployment, or use "Cập nhật thumbnail" to regenerate them. Vimeo requests carry only video metadata, never learner records or learning events. Detailed learning progress and surveys remain internal; marketing events use the root browser Pixel and Google Tag configuration. Vimeo keeps DNT playback.

`node scripts/test-dong-tien-admin.cjs --browser` validates admin API permissions, statistics, configuration persistence and browser edits with isolated storage. Add `--cta` to the real-video browser command below to verify a timed CTA, its new-tab link and its view/click events.

`node scripts/test-dong-tien-vimeo.cjs` verifies link parsing, title/duration/privacy hash lookup, thumbnail caching and restricted request destinations with mocked Vimeo responses.

With the local page running, `node scripts/test-learning-browser.cjs pages/dong-tien/course-catalog.json [--course trading] --play-video` checks registration, login, the real first Vimeo video and watched coverage using isolated test storage. It creates no CRM test leads in the running admin database.
